# i18n в tusten — руководство пользователя

Локализация клиентских модулей: ключ — это текст на исходном языке, словари лежат рядом
с модулем, SSR отдаёт готовый перевод и не даёт hydration mismatch.

> Как это устроено внутри и что ещё не сделано — `dev_docs/i18n-roadmap.md`.
> Краткая версия — раздел «i18n» в корневом `README.md`.

## Что умеет

- `import rk from 'i18n!HomePage'` — функция перевода конкретного клиентского модуля.
- Словари — обычные JSON: `client/<Module>/lang/<locale>/<locale>.json`.
- Нет словаря, локали или ключа — возвращается сам ключ. **Без ошибок и warning'ов.**
- `template()` — подстановки `{name}` и ICU-plural (`one` / `few` / `many` / `other`, `=N`).
- Язык определяется на сервере: cookie → `Accept-Language` → `defaultLocale`.
- SSR встраивает переводы в HTML, поэтому гидрация проходит без mismatch.
- `setLocale('en')` ставит cookie и перезагружает страницу.
- `<html lang="…">`, `Vary: Accept-Language, Cookie`, отдельные чанки словарей.

## Быстрый старт

1. Включите фичу в `tusten.config.ts`:

    ```ts
    import { defineConfig } from '@tusten/core'

    export default defineConfig({
        i18n: { defaultLocale: 'ru', locales: ['ru', 'en'] },
    })
    ```

2. Создайте словари рядом с модулем:

    ```
    client/HomePage/lang/ru/ru.json
    client/HomePage/lang/en/en.json
    ```

    ```json
    {
        "Помощь": "Помощь",
        "Привет, {name}!": "Привет, {name}!",
        "{n, plural, one {# файл} few {# файла} many {# файлов} other {# файла}}": "{n, plural, one {# файл} few {# файла} many {# файлов} other {# файла}}"
    }
    ```

    ```json
    {
        "Помощь": "Help",
        "Привет, {name}!": "Hello, {name}!",
        "{n, plural, one {# файл} few {# файла} many {# файлов} other {# файла}}": "{n, plural, one {# file} other {# files}}"
    }
    ```

3. Используйте в компоненте:

    ```tsx
    import { template } from '@tusten/core/client'
    import rk from 'i18n!HomePage'

    export function View(): JSX.Element {
        return <h1>{template(rk('Привет, {name}!'), { name: 'Аня' })}</h1>
    }
    ```

4. Перезапустите dev-сервер (реестр словарей снимается на старте) и проверьте:

    ```bash
    curl -H "Accept-Language: en" http://127.0.0.1:3000/
    ```

## Конфиг

```ts
export interface TustenI18nConfig {
    /** Имя cookie с выбранным языком. По умолчанию `lang`. */
    key?: string
    /** Основной язык: на нём написаны ключи. Обязан входить в `locales`. */
    defaultLocale: string
    /** Все поддерживаемые языки: `lang/<locale>/<locale>.json`. */
    locales: string[]
}
```

```ts
export default defineConfig({
    i18n: {
        key: 'lang', // cookie; по умолчанию `lang`
        defaultLocale: 'ru',
        locales: ['ru', 'en'],
    },
})
```

Правила валидации (нарушение — `TustenError` при загрузке конфига):

- `locales` — непустой массив; формат locale `en`, `pt-BR` (буквы, цифры, дефисы).
- `defaultLocale` обязан входить в `locales`.
- Дубликаты в `locales` молча убираются.
- `key` — токен cookie по RFC 6265: пустая строка, пробелы, `;`, `=`, `,` запрещены.

Особенности:

- **Секции `i18n` нет** — фича выключена: `rk(key)` всегда возвращает `key`,
  `<html lang>` не выводится, словари не сканируются.
- **`locales` не читается на клиенте.** Клиент не видит `tusten.config.ts`, поэтому
  список языков для переключателя дублируйте в коде (см. [переключатель](#переключатель-языка)).
- **Cookie по умолчанию — `lang`.** В beta.5 было `tusten_locale`; чтобы сохранить старое
  поведение: `i18n: { key: 'tusten_locale', ... }`.

## Словари

Путь: `client/<Module>/lang/<locale>/<locale>.json`, где `<Module>` — **имя папки верхнего
уровня** в `client/`. Импорт `i18n!HomePage` ищет `client/HomePage/`.

```
client/
├── HomePage/
│   ├── View.tsx
│   └── lang/
│       ├── en/en.json
│       └── ru/ru.json
└── shared/
    └── lang/en/en.json   → import rk from 'i18n!shared'
```

Требования к файлу:

- Корень — JSON-объект `{ "ключ": "перевод" }`, значения **только строки**.
- Битый JSON, массив/скаляр в корне или нестроковое значение → `TustenError` на сборке
  (в dev — на старте сервера), с путём до файла.
- Отсутствующий словарь — не ошибка: эта локаль просто не переводится.
- **Словарь для `defaultLocale` не обязателен:** ключ уже написан на этом языке и будет
  возвращён как есть. Держите `ru.json` как файл для переводчиков и для проверки
  ICU-шаблонов — это поддерживается.
- Реестр словарей сканируется **один раз на старте**. Новый файл или новая локаль
  подхватятся после перезапуска dev-сервера; правка уже существующего JSON вызывает
  полную перезагрузку страницы (HMR-границы у словарей нет).

## Импорт и использование `rk`

```ts
import rk from 'i18n!HomePage'

rk('Помощь') // "Help" в en, "Помощь" в ru
rk('Помощь', 'Поддержка') // сначала "Поддержка@@Помощь", потом "Помощь"
```

- Единственный пользовательский синтаксис — `i18n!<Module>`. `i18n:<Module>` — внутренний
  virtual module, его резолвит только плагин; писать так нельзя.
- Имя модуля совпадает с папкой **точно** (регистр важен).
- `rk` синхронная: она только ищет в уже загруженном словаре. Загрузку делает
  фреймворк (SSR-гидрация, чанк маршрута).
- Типы приходят автоматически через `@tusten/core/client` (ambient `declare module 'i18n!*'`).
  Если React-типы не нужны, подключите явно: `/// <reference types="@tusten/core/i18n" />`.
- `i18n!<Module>` — virtual module Vite. В серверном коде (RPC, loaders, jiti, скрипты)
  импортировать его нельзя — только в клиентских модулях, которые собирает Vite.

Вызывайте `rk` **во время рендера** (в теле компонента или функции), а не на верхнем
уровне модуля: до гидрации/загрузки чанка словарь может быть ещё не засеян.

## Ключи и контекст

- Ключ — **текст на исходном языке**, а не абстрактный id. Отсутствующий перевод просто
  покажет этот текст.
- Lookup: `ctx@@key` → `key` → сам `key`.
- `ctx` — второй аргумент, разделяет омонимы:

    ```json
    {
        "Кнопка@@Отмена": "Cancel button",
        "Диалог@@Отмена": "Cancel dialog"
    }
    ```

    ```ts
    rk('Отмена', 'Кнопка')
    rk('Отмена', 'Диалог')
    ```

- Пустая строка как перевод считается отсутствующей — вернётся ключ.
- Ключи с ICU-шаблоном (plural) должны совпадать в словаре **буква в букву** с вызовом,
  включая пробелы: ключ — обычная строка JSON.

## `template()`: интерполяция и plural

```ts
import { template, getLocale } from '@tusten/core/client'

template('Привет, {name}!', { name: 'Аня' })
template('{n, plural, one {# файл} few {# файла} many {# файлов} other {# файла}}', { n: 5 })
template(str, params, 'en') // locale можно передать третьим аргументом
```

Поддерживаемое подмножество ICU:

| Синтаксис              | Поведение                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| `{name}`               | Подстановка значения. Нет параметра (или `null`/`undefined`) — плейсхолдер остаётся как есть, без исключения |
| `{n, plural, …}`       | Форма выбирается через `Intl.PluralRules(locale)`. Форма `other` **обязательна**                             |
| категории              | `zero`, `one`, `two`, `few`, `many`, `other`                                                                 |
| `=N`                   | Точное совпадение, проверяется раньше категорий: `=0 {нет файлов}`                                           |
| `#`                    | Число внутри формы plural, форматируется через `Intl.NumberFormat` (`1 234` в ru)                            |
| `\{`, `\}`, `\#`, `\\` | Экранирование литералов. Прочие `\` — обычный текст (например, `C:\path`)                                    |

Что важно знать:

- Значение plural приводится к числу. Строка с числом тоже подойдёт; нечисло — плейсхолдер
  остаётся в выводе.
- Нет подходящей категории — берётся `other`.
- **Вложенный plural не поддерживается**; `select` тоже не поддерживается.
- Синтаксически битый шаблон (незакрытая `{`, отсутствие `other`, вложенный plural)
  бросает `TustenError` **при рендере**. Сломанный перевод дойдёт до ErrorBoundary.
  Проверяйте словари тестами (см. [Тесты](#тесты)).
- Результат `template()` не кэшируется по параметрам, но разобранные шаблоны кэшируются —
  вызывать в рендере дёшево.
- Locale по умолчанию — `getLocale()`; при выключенном i18n это `undefined`, и plural
  считается по локали окружения.

## Текущий язык

```ts
import { getLocale, setLocale } from '@tusten/core/client'
```

- `getLocale(): string | undefined` — язык текущей страницы. `undefined`, если i18n выключен
  или страница ещё не инициализирована.
- `setLocale(locale: string): void`:
    - проверяет формат locale (`TustenError` на мусор);
    - пишет cookie с именем из `i18n.key` (`path=/`, `max-age` год, `SameSite=Lax`);
    - вызывает `window.location.reload()`.
    - Вне браузера (SSR, тест без DOM) бросает `TustenError`.
- **Реактивного переключения нет.** Язык — константа на время жизни страницы: от неё зависят
  словари и SSR-разметка. Поэтому смена языка = cookie + перезагрузка.

Как сервер выбирает язык (`resolveRequestLocale`):

1. cookie `i18n.key` — но только если значение входит в `locales`;
2. `Accept-Language` с учётом `q`: сначала точное совпадение, затем основной подтег
   (`en-GB` → `en`); `q=0` и `*` игнорируются;
3. `defaultLocale`.

Cookie важнее заголовка: это явный выбор пользователя.

## Переключатель языка

Клиент не знает `i18n.locales`, поэтому список дублируется:

```tsx
import { getLocale, setLocale } from '@tusten/core/client'

/** Должен совпадать с `i18n.locales` в tusten.config.ts. */
const LOCALES = ['ru', 'en'] as const

export function LocaleSwitcher(): JSX.Element {
    const current = getLocale()
    return (
        <div>
            {LOCALES.map((locale) => (
                <button key={locale} onClick={() => setLocale(locale)} disabled={locale === current}>
                    {locale}
                </button>
            ))}
        </div>
    )
}
```

Неизвестный locale в cookie сервер отбросит и вернётся к `Accept-Language` / `defaultLocale` —
поэтому держите список в синхроне с конфигом.

## SSR, гидрация и кэш

- SSR определяет locale запроса, кладёт её в `AsyncLocalStorage` (параллельные запросы
  разных языков не смешиваются) и рендерит страницу с этим языком.
- Переводы модулей, у которых `rk` **реально вызывался** при рендере, встраиваются в HTML.
  Клиент засеивает их синхронно до `hydrateRoot` — mismatch не возникает.
- Модули, которые создаются лениво (`React.lazy` внутри компонента), на сервере не
  предзагружаются: их словари догрузятся на клиенте, а `rk` до загрузки вернёт ключи.
- `<html lang="…">` выводится на SSR, SPA и 404-страницах. При выключенном i18n атрибута нет.
- На HTML-ответах с включённым i18n ставится `Vary: Accept-Language, Cookie` — иначе
  кэш (CDN, прокси) отдаст чужой язык. Если кэшируете страницы сами, учитывайте это.

## SPA-навигация

При переходе по ссылке словарь нужного модуля подгружается отдельным чанком вместе с
маршрутом, после чего `rk` начинает переводить. До этого момента возвращаются ключи —
на практике чанк приходит быстрее, чем пользователь успевает прочитать текст.

Если после навигации переводы не появились, проверьте:

- модуль импортируется статически из маршрута (а не через `React.lazy` внутри компонента);
- имя модуля в `i18n!<Module>` совпадает с папкой;
- словарь для текущей locale существует и был в реестре на старте сервера.

## Ограничения и частые ошибки

| Симптом                               | Причина / решение                                                                                                           |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Все ключи на месте, перевода нет      | Нет словаря для этой locale; имя папки/модуля не совпадает; забыли перезапустить dev-сервер после добавления файла          |
| `rk` вернул ключ                      | Ключа нет в JSON, перевод пустой (`""`) или locale не определена (`getLocale()` → `undefined`)                              |
| `Cannot find module 'i18n!X'` в `tsc` | Не подключены типы: импортируйте что-то из `@tusten/core/client` или добавьте `/// <reference types="@tusten/core/i18n" />` |
| `i18n!X` не резолвится в Vitest       | Подключите `i18nTestPlugin()` (см. [Тесты](#тесты))                                                                         |
| `Invalid JSON in i18n dictionary`     | Битый JSON — ошибка сборки, исправьте файл                                                                                  |
| `value for key "…" must be a string`  | Число/объект как перевод: приведите к строке                                                                                |
| `TustenError` про plural при рендере  | В шаблоне нет `other`, незакрытая `{` или вложенный plural                                                                  |
| Смена языка не сработала              | `setLocale` вызван не в браузере или locale не входит в `locales`                                                           |
| Словарь не обновился в dev            | Правка JSON делает полную перезагрузку; новый файл — только после рестарта сервера                                          |
| После деплоя старый язык              | Забыт `Vary: Accept-Language, Cookie` на кэширующем слое                                                                    |

## Тесты

В `vitest.config.ts` подключите заглушку: в тестах `i18n!<Module>` резолвится в модуль,
где `rk(key)` возвращает `key`. Словари и locale в тестах не участвуют.

```ts
// vitest.config.ts
import { defineConfig } from 'vitest/config'
import { i18nTestPlugin } from '@tusten/core/server'

export default defineConfig({
    plugins: [i18nTestPlugin()],
})
```

Если нужно проверить сами словари, читайте их как JSON в тесте и валидируйте `template()`:

```ts
import { readFileSync } from 'node:fs'
import { template } from '@tusten/core/client'
import { describe, expect, it } from 'vitest'

describe('HomePage/en', () => {
    const dict = JSON.parse(readFileSync('client/HomePage/lang/en/en.json', 'utf8')) as Record<string, string>

    it('все шаблоны рендерятся', () => {
        for (const value of Object.values(dict)) {
            expect(() => template(value, { n: 1, name: 'x' }, 'en')).not.toThrow()
        }
    })
})
```

## Диагностика

```bash
pnpm inspect:basic   # или: tusten inspect
```

Секция `i18n` показывает: `defaultLocale`, список `locales`, по каждому модулю — число
ключей для каждой locale, `—` для отсутствующего словаря и `ERROR` для битого JSON.
Данные берутся теми же `scanI18n` / `parseDictionary`, что и в сборке, — расхождений нет.
